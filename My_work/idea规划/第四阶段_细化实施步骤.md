# WP0：研究协议冻结

目标：在数据采集、分类、建模之前冻结研究边界、时间窗口、预测任务、回测方案、评价指标和主要基线，避免后续因研究口径变化造成返工。

## WP0.1 固定研究问题

- RQ1：AI赋能网络安全技术在科学研究、专利、开源生态和漏洞需求之间存在怎样的演化、领先—滞后和技术融合规律？
- RQ2：多源历史科技情报能否有效校准技术状态转移和扩散参数，从而减少传统动态推演对专家主观参数的依赖？
- RQ3：ECDS-TF 是否能够比统计模型、机器学习、动态图模型以及传统 ABM 更准确地预测技术成长、新兴技术和技术融合？
- RQ4：ECDS-TF 能否通过历史时间切片回测重建已经发生的 AI 网络安全技术演化？
- RQ5：不同外部冲击情景下，2027—2030 年 AI 赋能网络安全技术的成长、融合与演化路径有何差异？

## WP0.2 固定研究时间

| 参数 | 设置 |
|---|---|
| 历史数据起点 | 2012Q1 |
| 历史观测终点 | 2026Q2 |
| 基本时间粒度 | Quarter |
| 最小预测窗口 | 4季度 |
| 中期预测窗口 | 8季度 |
| 长期预测窗口 | 12季度 |
| 最终推演 | 2026Q3–2030Q4 |

## WP0.3 固定三个主要预测任务

### Task A：Technology Growth Forecasting

预测未来 4/8/12 个季度技术增长状态。主要指标：MAE、RMSE、sMAPE。

### Task B：Emerging Technology Detection

识别未来进入快速增长阶段的技术。主要指标：Precision@K、Recall@K、NDCG@K、AUPRC。

### Task C：Technology Convergence Forecasting

预测技术之间未来融合关系。主要指标：AUC、F1、Hits@K。

### 约束

“技术成熟度”暂不作为主要监督标签，以避免因主观 maturity ground truth 导致循环论证；后续作为综合派生指标和2030预见输出。

# WP2：AI for Cybersecurity 技术分类体系

目标：形成可跨论文、专利、GitHub、CVE 对齐的统一 Technology Entity 体系。

## 一级技术族 V1

- T01 AI Vulnerability Discovery
- T02 Automated Program Repair
- T03 AI Malware Analysis
- T04 AI Intrusion Detection
- T05 AI Network Anomaly Detection
- T06 AI Threat Intelligence
- T07 AI Threat Hunting
- T08 AI SOC / Security Agent
- T09 Automated Incident Response
- T10 AI Security Orchestration
- T11 AI Digital Forensics
- T12 AI Phishing/Fraud Detection
- T13 AI Attack Surface Management
- T14 AI Cyber Deception
- T15 AI Software Security Analysis

## 分类方法

NIST/MITRE/CWE 等领域知识 + Seed Keywords + Embedding + BERTopic/HDBSCAN + 人工复核。

目标形成 Expert-guided Data-driven Taxonomy。

## Pilot Corpus

第一轮不做全量数据，先约 2500 条：

- 论文：1000
- 专利：500
- GitHub：500
- CVE/CWE：500

人工抽样检查约 300 条，记录 Precision、Recall、F1，必要时计算 Cohen's Kappa。

# WP3：STOV 多源数据工程

STOV = Science + Technology + Open Source + Vulnerability。

## Science

优先使用 OpenAlex Snapshot；保留 work_id、title、abstract、publication_date、topics、keywords、citations、authors、institutions、referenced_works。

## Technology

优先使用 PatentsView bulk data，API 作为补充；保留 patent_id、title、abstract、claims、date、CPC、assignee、inventor、citations。

## Open Source

GitHub 两阶段策略：先检索相关仓库，再重建 repo/activity 时间序列；保留 created_at、stars、forks、contributors、commits、issues、releases、topics、language、dependencies。

## Vulnerability

优先 NVD 2.0 JSON feeds；保留 CVE_ID、published、modified、CWE、CVSS、CPE、description、references、KEV。

# WP4：跨源实体对齐与图构建

目标：把不同数据源中的表达映射到统一 Technology_ID。

## 三级对齐

1. 词典/规则匹配
2. Embedding similarity
3. LLM/人工复核边界样本

核心输出：`technology_mapping.parquet`

字段：source_type、source_id、technology_id、confidence、method、reviewed。

## 时序异构图

每季度构造 `G_t=(V_t,E_t)`。

节点建议包括：Technology、Paper、Patent、Repository、CVE、Organization。

边建议包括：cites、implements、relates、fixes、targets、develops、converges、shares_topic。

# WP6：ECDS-TF 渐进实现

## ECDS-v0

仅做 Evidence-Calibrated State Transition：

`X_{t+1}=A X_t + B D_t + ε`

验证数据校准动态推演是否成立。

## ECDS-v1

增加 Lead-Lag 机制，学习 Paper→GitHub、CVE→Research、GitHub→Patent 等跨源时滞关系。

## ECDS-TF

加入 Temporal Heterogeneous Graph：

`H_t = TGNN(G_{1:t})`

`X_{t+1}=F(X_t,H_t,D_t,Z_t)+ε`

# WP7：历史回测、消融和稳健性验证

## 核心 Backtest

|---|---|---|
| F1 | 2012–2018 | 2019–2021 |
| F2 | 2012–2020 | 2021–2023 |
| F3 | 2012–2022 | 2023–2025 |

# WP8：2027–2030 动态推演

最终训练窗口：2012Q1–2026Q2。

推演窗口：2026Q3–2030Q4。

## 情景

- Scenario 0：Baseline
- Scenario 1：AI Acceleration
- Scenario 2：Threat Shock
- Scenario 3：OSS Acceleration
- Scenario 4：Constraint

每个情景建议 Monte Carlo `N=1000`。

主要输出：P(Emergence)、P(HighGrowth)、P(Convergence) 及 95% 区间。

## MAF-TF 智能体压力测试

LLM 多智能体不参与主要历史性能排名，仅用于 2027–2030 prospective scenario stress test。

Agent：Scientist、Industry、Open-source、Cyber Defender、Technology Analyst。

输出：采用障碍、制度因素、监管风险、商业约束、技术瓶颈、极端事件，以及与 ECDS-TF 的一致/分歧分析。
