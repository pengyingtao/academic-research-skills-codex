6. 引入 GitHub `artifact_type` 和 offensive/defensive orientation；
7. 冻结 2500 条 Pilot Corpus 的字段 schema 与 sampling manifest。

### Sanity Check 关键案例

- LLM vulnerability repair / security patch 论文 → T02，必要时 secondary T01；
- generic automated program repair 无 security context → 排除；
- 网络异常/流量检测专利即使标题写 vulnerability，也可能是 T04 而不是 T01；
- `xalgorix/xalgorix` 同时包含 AI + vulnerability detection，但主要目标为 autonomous pentesting / exploitation orchestration → `OFFENSIVE_ONLY`，从 AI-for-Cybersecurity supply corpus 排除；
- `FunnyWolf/agentic-soc-platform` 明确为 agentic SOC / blue-team / SIEM / SOAR → T09，可能 secondary T10；
- awesome-list/catalog 作为生态发现辅助，不与真实工具等权计算工程活跃度。

### V-source 结构性修订

原方案中 `cve_related` 不再参与 T01–T15 直接分类。

新方案：

- CVE/CWE/KEV/EPSS → Vulnerability Demand Pressure；
- 保存 weakness group、CVSS、KEV、EPSS、CPE/vendor/product 等 point-in-time 特征；
- 与 T01–T15 的关系仅作为 `hypothesized_pressure_targets`，在后续模型中估计，不作为 supervised ground truth；
- VDP 聚合权重在 WP2 不人工冻结，优先保留 feature vector，由后续 Evidence Calibration 学习。
